# Details:
1. Implement dual interface approach:
   a. Wizard pattern for recipe creation
   b. Modal-based editing for existing recipes

2. Create Recipe Creation Wizard with:
   a. Left sidebar progress tracker (Recipe Details → Parameters → BOM → Mashing Protocol)
   b. Sequential navigation with Next/Cancel buttons
   c. Save Recipe option available at any step
   d. Component reuse between creation and editing interfaces

3. Develop Recipe Details step (initial wizard step):
   a. Recipe Name input with intelligent defaults
   b. Active Status toggle checkbox (default: checked)
   c. Whiskey Type dropdown selection (RyeBourbon, WheatBourbon, etc.)
   d. Revision field (auto-populated as "1" for new recipes)
   e. Customer Name dropdown selection
   f. Cooks Per Fermenter numeric input (default: 4)
   g. Mashing Protocol template selection dropdown
   h. Auto-timestamp creation (Created on [date] by [user])

4. Implement three-tab recipe structure for both wizard steps and editing modals:
   a. Bill of Materials tab - Comprehensive ingredient management
   b. Parameters tab - Process control settings for production
   c. Mashing Protocol tab - Step-by-step production instructions

5. Develop Bill of Materials interface with:
   a. Multiple ingredient category support (Water, Backset Water, Grains, etc.)
   b. Chemical additives management (Citric Acid, etc.)
   c. Biological components tracking (Yeast, Enzymes)
   d. Precise quantity tracking with appropriate units
   e. Ingredient code standardization system
   f. Real-time BOM calculations and validation
   g. Cost estimation during creation

6. Implement Parameters tab with:
   a. Proof control settings (HighWineProof, LowWineProof)
   b. Process settings (BaseLoss, BeerFeedTray, CooksPerFerm)
   c. Operational parameters (TopOffFrequency, MashRatio, RatioByFerm)
   d. Quality controls (StarterSweetoH, IsFourGrain)
   e. Validation before proceeding to next step

7. Create Mashing Protocol interface with:
   a. Sequential process step management (LiquidAdd, Hold, AdditiveAdd, etc.)
   b. Process control fields (Index, Step Type, Hold Type, Temp SP, Time)
   c. Temperature management (Heat and Cool hold types with specific timing)
   d. Step validation and sequencing logic
   e. Process validation and sequencing

8. Implement wizard UX features:
   a. Progressive disclosure: Only show relevant fields for current step
   b. Draft saving: Save Recipe button available at any step for incomplete recipes
   c. Validation gating: Prevent progression to next step if current step invalid
   d. Step navigation: Allow jumping between completed steps
   e. Wizard state management: Maintain form data across steps
   f. Template integration: Allow starting from existing recipe templates or protocols

9. Implement ingredient selection that supports mash bill patterns (e.g., 75-21-00-04)

10. Add recipe parameter validation with constraints for different whiskey types

11. Implement recipe cost calculation and yield prediction

12. Add recipe scaling calculations for different batch sizes

13. Create form validation for required fields and business rules

14. Implement save, submit, and cancel functionality with revision tracking (R01, R02, etc.)

15. Design improved recipe card layout with better information hierarchy for Recipe ID, Type, Revision, Customer, Item Number, Created date/email

16. Implement responsive grid layout that adapts to different screen sizes

17. Create advanced filtering system for recipes by mash bill, whiskey type, revision, and customer

18. Add grouping options for recipes (by customer, recipe type, mash bill)

19. Implement enhanced sorting options beyond "Newest First"

20. Support Recipe ID format: [CUSTOMER]-[MASH_BILL]-R[REVISION] (e.g., JBM-75-21-00-04-R01)
